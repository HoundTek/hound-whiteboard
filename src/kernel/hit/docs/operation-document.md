# 操作文档

本文档记录 Undo/Redo 体系中操作模型的设计意图与实现语义。

> [!NOTE]
>
> **实现状态**：分子操作记录结构、commit 边界单管线（`HitCommitter` + `BoardApi` 记录化）、三级容器模型（增量式分子 `molId`、超分子 `supraId` 即时物化与 close-supra 聚合折叠、discard 型取消选择）、撤销与重做的运行时语义均已落地（`src/kernel/hit/`）；旧日志形态（`supraOpId` 草稿凝聚）只读兼容。trash 已随布局 v2 持久化（板根 `trash/{objectId}.json`，日志按 source 分片 `hit/{source}/seg-{NNNNNN}.jsonl`、元数据分片 `meta/{source}.json`，日志跟随者指纹调和，见[文件结构文档](../../../docs/file-structure.md)）；`move-head` 的应用入口待后续落地。

## 操作层级

操作分三级：

- **原子操作** — 帧增量（amend 流），发生在 AOM 动态图中，不产生 hit 节点、永不落盘，被 endMol 吸收。
- **分子操作** — 一次手势或单步修改凝聚的独立可撤销单元，hit 节点的携带单位，内核共享树的生长单位。
- **超分子操作** — 一次「选择 → 修改 → 提交」会话，多个分子操作的有序组合，撤销与协作的粒度单位。

hit 节点的粒度只有分子操作与超分子操作两种，合称**节点粒度**。

```mermaid
flowchart LR
    subgraph supra["超分子操作"]
        direction TB
        m1["分子操作"] --> m2["分子操作"] --> m3["分子操作"]
    end
    atom["原子操作 × N<br/>"] -- "endMol 凝聚" --> m1
```

## 原子操作

原子操作多为采样点级别：书写时的采样点追加、拖拽中的帧位移等瞬时变化。原子操作发生在 AOM 动态图中，不进 hit、永不落盘；进行中经 amend 事件流（begin-mol / amend / end-mol / abort-mol）向远端 volatile 广播（只画不存），同一手势的全部原子操作在 endMol 时被吸收、凝聚为分子记录上链——分子 = 一次手势：每次 beginMol 分配独立 molId、endMol 即物化；多手势操作（多手势的对象创建、修改）的各次手势各自成录，经 supra key 汇聚为超分子（见「超分子操作」）。

## 分子操作

分子操作按**作用对象**分为两类：

- **对象级操作**： 改变白板内容或对象的图层归属
- **树级操作**： 改变 hit 自身

分子操作按**对 hit 的作用**分为四类：

- **增加节点类**： 在 HEAD 之后追加节点：增加对象、修改对象、删除对象、选择对象、取消选择对象
- **移动指针类**： 更改 HEAD 指针
- **改挂类**： 撤销与重做：撤销在目标节点的父节点处分叉并改挂后续链（目标为活动链末端时退化为纯 HEAD 回退）；重做把撤销目标节点按时间标记重新激活（插回活动链）
- **折叠类**： 闭合超分子（close-supra）：把活动链上同 supraId 的连续节点段折叠为聚合节点，自身不产生节点

分子操作按**作用域**分两组：

- **作用在白板上**：增加、修改、删除、选择、取消选择对象——效果落在白板文档状态上，可被撤销操作抵消。
- **作用在时间回溯树上**：撤销、重做、更改 HEAD 指针、闭合超分子——效果落在树的结构与指针上；撤销与重做经树的结构与指针变化抵消或恢复白板操作的效果，白板状态随投影联动。

分子操作有两种物化形态：

- **增量式分子**：以 `beginMol → amendMol → endMol/abortMol` 生命周期承载一次手势；开启时分配 molId，进行中只产生 amend 流（原子，永不落盘），`endMol` 物化为分子记录（每对象一条、同 molId），`abortMol` 丢弃 amend 流不留痕。同 molId 且同 supraId 的相邻记录在树上归并为一个分子节点。

```mermaid
sequenceDiagram
    participant T as 调用方（工具）
    participant H as HitCommitter
    participant L as 操作日志 / hit 树
    T->>H: beginMol（分配 molId）
    loop 手势帧 × N
        T->>H: amendMol（原子帧增量）
        Note over H: amend 走 volatile 通道<br/>只画不存、永不落盘
    end
    alt 正常结束
        T->>H: endMol
        H->>L: 物化分子记录上链（每对象一条、同 molId）
    else 取消
        T->>H: abortMol（丢弃 amend 流，不留痕）
    end
```
- **即时式分子**：无生命周期，提交即物化上链（无 molId），与旧日志形态一致；选择、取消选择等单步操作为此形态。

### 操作无法撤销

日志只增不删，任何操作一经记录永久留在日志中。撤销操作撤销的是目标操作在白板上的效果——效果由新操作抵消，原操作仍在日志中、可溯源。树操作中：撤销的效果由重做抵消，更改 HEAD 指针可再次移动。

节点注解（标记关键点、注释节点）归 UI 层，不进 hit。

### 分子操作的记录

记录的公共字段：

- `id`：操作 id，形如 `"{source}/op-{n}"`，复用 id 命名空间（见[时间回溯树内核文档](undo-tree-kernel-document.md)）。
- `type`：操作类型（九类：八类分子操作 + 闭合超分子记录，见下）。
- `source`：发起者标识，即 hit 节点的 author。
- `time`：毫秒物理时间标记；全序按（时间, author）时钟环决胜，同 author 再按操作序号决胜。
- `parentId`：创建时本地视角的父节点 id（根为 `null`）；建树以时间序为准。
- `supraOpId`：旧日志形态（草稿凝聚）的超分子关联（首分子自指），只读兼容；三级容器模型的新记录不写，恒为 `null`。
- `molId`：增量式分子 id，形如 `"{source}/mol-{n}"`；仅增量式分子的增加/修改对象记录携带，即时式分子为 `null`。
- `supraId`：归属超分子 id，形如 `"{source}/supra-{n}"`；独立分子为 `null`；仅增加节点类操作可携带。
- `discard`：放弃型闭合标志，仅取消选择有意义：`true` 表示放弃修改、回选择前快照（载荷携带 `restore` 还原点）；缺省 `false`。
- `properties`：涉及属性的集合（如 `position`、`property`、`data.points`），冲突合并的判定粒度。
- `payload`：类型载荷（形状见各操作）。

快照与层位边：修改前后快照——undo 用前快照回退，协作用后快照传播；删除的对象移入 trash（板根 `trash/`），记录携带对象快照与层位边，代替后快照。层位（z-order）信息以**层位边**承载——逐覆盖区块的 `{chunkId, below, above}`（below = 主体之下的对象，above = 主体之上的对象）：选择对象携带选择时刻的提取边（撤销选择或整个会话时凭以恢复），取消选择与增加对象携带写回静态图后的提交边（重放/远端凭以应用，不经本地重算），修改对象仅绕过 AOM 会话直接改静态图且伴随边变更时携带前后两组层位边（擦除回写），删除对象携带删除时刻的层位边。层位恢复的统一缝合规则：记录之外的相交对象按先后判定上下——正放（增加、修改、取消选择）缝「后写者居上」（主体居上），历史恢复（撤销路径）缝「较晚物化的一方居上」（主体居下）；应用提交边先全清主体边再按记录重写，同一相交对的并发反向主张由日志序后者覆盖（Last Write Win），两端收敛一致。旧日志形态的层栈快照（layerStackSnapshot，操作时刻的完整 z-order 数组）只读兼容——新记录不携带，重放无层位边时回退几何居上。

三个原则：

- **分子操作的边界是提交的效果**：单手势操作（一笔画线、一次拖动）以增量式分子承载——beginMol 开启、手势帧走 amend 流、endMol 物化凝聚；多手势操作（多手势的对象创建、对象修改）的每次手势各自物化为独立分子记录，经 supra key 汇聚为超分子。Core 侧入口已收口（`BoardApi.eraseData`、AOM `apply`），在单点按提交时机包装。
- **不跨端重放操作语义**：同步复制的是效果（快照），各端直接应用快照，免除跨端重放操作语义（如切割几何）的逐字节一致性要求。
- **操作为王**：操作是一等记录（id、author、时间、内容），可产生多个节点；树是日志的追溯结构，节点数据放在数据池中凭 id 获取。移动指针类操作不产生节点，也可入日志。

### 增加对象

向静态图添加某对象。记录区块 id、对象 id、对象全量内容；携带提交时刻主体在各覆盖区块的层位边（创建手势物化时主体未入静态图则省略，重放回退后到者居上），供撤销与层位修复恢复层位关系。

载荷：`{ chunkId, objectId, data, chunks? }`——`data` 为对象全量内容（可 JSON 序列化，`deserialize` 可重建实例）；`chunks` 为逐覆盖区块的 `{chunkId, below, above}` 层位边。

### 修改对象

修改某对象的属性、数据或层位关系。记录区块 id、对象 id、涉及属性集合、修改前后快照。z-order 调整（置顶、置底、上移、下移）视为修改对象，层位变化经配对的选择/取消选择记录的层位边表达。

载荷：`{ chunkId, objectId, before, after, chunks? }`——`before`/`after` 为修改前后的全量快照；涉及属性集合承载在记录的 `properties` 字段；`chunks` 为 `{before, after}` 两组层位边，仅绕过 AOM 会话直接改静态图且伴随边变更的修改携带（擦除回写）——手势会话的层位变化由 choose/unchoose 记录承载，普通修改不携带。

### 删除对象

从静态图删除某对象。记录区块 id 与对象 id，对象移入 trash（板根 `trash/`）。

载荷：`{ chunkId, objectId, data, chunks }`——`data` 为删除时刻的对象全量快照，`chunks` 为对象在各区块的层位边（`below` / `above` 前驱后继）；记录携带对象快照与层位边，接收端凭以重建 trash 条目；撤销删除时按 trash 中的本体与层位边恢复。

### 选择对象

将对象选入 AOM。选择改变对象的图层归属，该操作可能进入 hit 内核；更多以超分子操作中的分子呈现，鲜有单独出现。

载荷：`{ chunkId, objectId, choice? }`——`choice` 为命名选择名，匿名选择不记录。

### 取消选择

将对象移出 AOM（提交回静态图，或放弃更改）。与选择对象配对：选择把对象提升到输出层，取消选择将其交回，图层归属变化是双向的。同样更多以超分子操作中的分子呈现（如拖拽 = 选择 + 修改 + 取消选择）。

放弃型闭合（discard）：记录的 `discard` 为 `true` 时表示放弃更改——对象退出活动层，状态回选择前快照（Esc 闭合路径，零撤销动作）；载荷携带 `restore` 选择前快照，重放/重做/远端凭以还原实例。

载荷：`{ chunkId, objectId, choice?, restore? }`——`choice` 为命名选择名（匿名不记录），`restore` 仅 discard 型闭合携带。

### 更改当前 HEAD 指针

HEAD 指向当前状态对应的节点。按「所有用户一致」原则：网络同步良好时，所有用户的 HEAD 指针相同，每个用户的 hit 也相同。因此更改 HEAD 是分子操作，记录在树中并同步到各用户。撤销与重做的指针效果由各自记录应用时算出，不产生 move-head 记录；move-head 的用途是移动至其它分支的导航（应用入口待落地）。

载荷：`{ targetNodeId }`。

### 撤销

撤销操作 D 在白板上的效果，D 缺省为本端来源最近的活动链节点（各撤各的），可显式指定。撤销本身也记录于日志——操作无法撤销，撤销抵消的是效果，D 本身仍留在日志中、可溯源。撤销记录**目标节点**；HEAD 移动是应用时算出的效果。应用规则：

1. 在 D 的父节点处分叉：把 D 与 HEAD 之间的链（不含 D）改挂到分叉点；原位置按 (时间, author, 操作序号) 截断保留——不晚于撤销操作的节点留下共享数据，晚于的只存在于撤销分支。
2. HEAD 移到新末端。
3. D 是活动链末端时，没有可改挂的节点，效果退化为 HEAD 回退到 D 的父节点。
4. D 不在活动链上（已被撤销）时，撤销无效，被吸收。

载荷：`{ targetNodeId, previousHeadId }`——`previousHeadId` 为撤销前的 HEAD 位置（树结构视图与可重做栈投影使用）。

离线期间的撤销在合并时按合并树上的目标节点位置应用：目标已被推到链中间时，撤销呈现分叉改挂的一般形态，离线意图被保留（见[时间回溯树内核情景推演](undo-tree-kernel-example.md)情景四）。

### 重做

重做凭 `targetUndoId` 引用一条已生效的撤销记录，把该撤销的目标节点按时间标记**重新激活**（插回活动链）：晚于链末端时追加并推进 HEAD，否则插在对应位置、原后继改挂为其子节点——并发远端工作留在链上不动，被撤节点回到其时间位置。生效判定是纯日志谓词，不依赖记录投递交错：

1. 引用的撤销已生效登记（被吸收、未生效的撤销不产生重做目标）；
2. 该撤销未被重做；
3. 该撤销未被**同源**新工作洗刷——同来源、按记录全序（时钟环 + 同刻同 author 按操作序号决胜）晚于撤销的增加节点类操作洗刷本端的重做资格（与经典编辑器的重做语义一致）；远端来源的新工作不洗刷（各端按同一时间序评估，结论一致）。

本端 `redo()` 先查资格再发射：无资格时不产生记录——**发射即生效**，一旦记录，各端按日志必然得出相同的生效结论。重做记录留在日志中、可溯源。

载荷：`{ targetUndoId }`——被重做的撤销记录 id。

### 闭合超分子

超分子会话的闭合信号（close-supra）。树级操作，无白板效果，自身不产生节点、不作为超分子成员（记录顶层的 `supraId` 恒为 `null`，待闭合的超分子 id 只在载荷中）。`endSupra(key)` 在该超分子的成员记录不少于 2 条时追加本记录（单成员超分子的折叠是恒等，不产生记录）；树构建见到本记录时，把活动链上同 supraId 的连续节点段逐段折叠为聚合节点——段内不少于 2 节点才折叠，已撤销分支上的成员不参与，成员被并发异节点分隔时按段分别折叠（退化），重复闭合幂等。

载荷：`{ supraId }`——待闭合的超分子 id。

## 超分子操作

多个分子操作按序合成一个超分子操作，作为整体成为撤销与协作的粒度单位。超分子承载一次「选择 → 修改 → 提交」会话。

例：一次 FD 擦除手势 = 修改对象（回写首段）+ 增加对象（分裂段，可有多个）+ 删除对象（整笔擦没）的顺序组合（见[对象擦除工具文档](../../../ui/devices-dag/tools/eraser/docs/object-eraser-document.md)）。选择对象更多作为超分子操作中的分子出现。

实现语义（已落地）：

- **指定式归属（supra key）**：超分子按键开启与闭合（`beginSupra(key)` / `endSupra(key)` / `abortSupra(key)`，谁开启谁关闭）；开启时分配超分子 id（`"{source}/supra-{n}"`）。分子操作显式指定自己要进入的超分子（效果摘要携带 `supraKey`，可跨通道序列化），未指定的提交永远独立成录、不受开启中的超分子影响——工具组合以会话 key 汇聚一次「选择 → 修改 → 提交」（如 handoff wrapper），无 key 的并发工作（如同时绘制新笔画）不会被吞入。
- **即时物化**：开启期间成员提交即时物化上链（记录携带 `supraId`），不缓冲草稿；成员在日志与树上各自独立有效。`endSupra(key)` 先强制闭合其下未闭合的增量式分子（endMol 物化），再按上节规则追加闭合超分子记录，触发聚合折叠。
- **异常中止**：`abortSupra(key)` 撤销全部活跃成员（已物化成员逐个撤销，在途分子 abortMol），取消不留净效果。
- **撤销粒度**：未闭合的超分子内 undo 落最近本端分子（分子级）；闭合后 undo 撤整个聚合节点。拖动中 undo 先把本端未闭合分子强制 endMol 物化再撤（`BoardApi.undo` 返回 `forcedEndMolIds`），保证所有效果都有记录可撤。Esc 闭合走 discard 型取消选择（restore 快照回选择前，零撤销动作）；undo 聚合节点时 commit 与 discard 殊途同归（回选择前、取消选择）。
- **旧形态兼容**：旧日志形态（`supraOpId` 草稿凝聚）只读兼容——重建时成员组凝聚为单节点，与新形态记录在同一棵树收敛（见[时间回溯树内核文档](undo-tree-kernel-document.md)）。
